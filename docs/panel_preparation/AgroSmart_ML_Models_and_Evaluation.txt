Soil Image Classification (MobileNetV2 CNN)2.1 Why MobileNetV2?MobileNetV2 was selected as the deep learning backbone due to its parameter efficiency and depthwise separable convolutions. With an inverted residual structure and linear bottlenecks, MobileNetV2 achieves high feature representation capabilities while maintaining a compact memory footprint ($3.5\text{M}$ base parameters), making it suitable for edge deployment and fast server inference.2.2 Model Architecture & Transfer Learning StrategyThe model employs transfer learning initialized with weights pre-trained on ImageNet:Base Backbone: MobileNetV2 truncated prior to the final classification layer, accepting $(224, 224, 3)$ inputs.Custom Classification Head:`GlobalAveragePooling2D()`: Compresses $7 \times 7 \times 1280$ feature maps into a 1280-dimensional feature vector.`Dropout(rate=0.3)`: Prevents co-adaptation of features.`Dense(units=128, activation='relu')`: Intermediate non-linear representation.`Dropout(rate=0.2)`: Regularization prior to classification.`Dense(units=4, activation='softmax')`: Outputs normalized probability distribution across the 4 soil classes.2.3 Two-Stage Training ProtocolTo prevent catastrophic forgetting of pre-trained weights, training followed a two-stage regime (`backend/ml_training/train_soil_cnn.py`):Stage 1 (Feature Extraction):Pretrained MobileNetV2 backbone completely frozen (`base.trainable = False`).Custom classification head trained with Adam optimizer ($\text{learning rate} = 10^{-3}$, categorical cross-entropy).Trained for 10 epochs (EarlyStopping stopped at epoch 9 on plateauing validation loss).Stage 2 (Fine-Tuning):Top 20 backbone layers unfrozen (`layer.trainable = True`).Batch Normalization Safeguard: All `BatchNormalization` layers explicitly kept frozen (`layer.trainable = False`) to prevent corrupting learned ImageNet population statistics on a small dataset.Low learning rate applied ($\text{Adam}, \text{learning rate} = 10^{-4}$) to gently adjust high-level convolutional kernels.Model checkpoint monitored `val_loss`, automatically restoring best weights.2.4 Dataset, Partitioning, and Leakage AuditDataset Composition: 671 deduplicated unique images across four major agricultural soil orders:Alluvial: 281 imagesBlack: 122 imagesClay: 114 imagesRed: 154 imagesStratified Split (70 / 15 / 15):Training Set (70%): 469 imagesValidation Set (15%): 101 imagesHeld-Out Test Set (15%): 101 imagesStrict Cryptographic Audit: Prior to training, MD5 hashes of all 671 images were computed and asserted across splits. The audit confirmed 0 duplicate hashes and 0 cross-split leakage, recorded in `backend/trained_models/soil_cnn_splits.json`.2.5 Verified Test Evaluation ResultsThe final model was evaluated on the held-out 101-image test set only after training was fully terminated. Results recorded in `backend/trained_models/soil_cnn_metrics.json`:$$\mathbf{\text{Test Accuracy: } 90.10% \quad (0.9010)} \qquad \mathbf{\text{Test Loss: } 0.3692}$$Detailed Per-Class Classification Report:Class	Precision	Recall	F1-Score	Support (Test Images)Alluvial	0.8723	0.9535	0.9111	43Black	0.9231	0.6667	0.7742	18Clay	0.9375	0.8824	0.9091	17Red	0.9200	1.0000	0.9583	23Macro Average	0.9132	0.8756	0.8882	101Weighted Average	0.9032	0.9010	0.8971	101Confusion Matrix:$$\begin{pmatrix}41 & 1 & 0 & 1 \4 & 12 & 1 & 1 \2 & 0 & 15 & 0 \0 & 0 & 0 & 23\end{pmatrix}$$Red soil achieved 100% recall (23/23 correctly identified with zero false negatives).Alluvial soil achieved 95.3% recall (41/43 correctly identified).Most common confusion occurred between Alluvial and Black soils (4 Black images classified as Alluvial due to dark organic river sediment).---3. Crop Recommendation Model (Random Forest)3.1 Algorithm & JustificationCrop recommendation uses a `RandomForestClassifier` with 100 estimator trees. Random Forest was selected over linear models and single decision trees because:Agricultural soil-climate interactions are non-linear (e.g., high nitrogen is beneficial only if adequate precipitation and neutral pH exist).Random Forest aggregates predictions across de-correlated decision trees (bagging + feature sub-sampling), preventing overfitting and providing calibrated class probabilities via `predict_proba()`.3.2 Features & Training DatasetFeatures (7 continuous parameters):`N`: Nitrogen ratio (mg/kg)`P`: Phosphorus ratio (mg/kg)`K`: Potassium ratio (mg/kg)`temperature`: Soil temperature (°C)`humidity`: Ambient air humidity (%)`ph`: Soil pH level ($0\text{--}14$)`rainfall`: Meteorological precipitation (mm)Dataset: Kaggle Crop Recommendation Dataset (`crop_recommendation.csv`), consisting of 2,200 rows with exactly 100 samples per class across 22 crops.22 Output Crop Classes: Rice, Maize, Chickpea, Kidneybeans, Pigeonpeas, Mothbeans, Mungbean, Blackgram, Lentil, Pomegranate, Banana, Mango, Grapes, Watermelon, Muskmelon, Apple, Orange, Papaya, Coconut, Cotton, Jute, Coffee.3.3 Inference Preprocessing & Top-3 RankingFeature Scaling: Inputs are transformed using a fitted `StandardScaler` (`crop_scaler.pkl`) saved during training.Missing-Value Imputation: If any parameter is omitted in manual entry, `app.ml.preprocessor.CropInferencePreprocessor` replaces the null value with training-set median values (N=40, P=25, K=180, Temp=26°C, Humidity=62%, pH=6.5, Rainfall=52mm), preventing inference crashes.Probabilistic Ranking: The model computes posterior probabilities for all 22 classes:$$P(c_i \mid \mathbf{x}) = \frac{1}{B} \sum_{b=1}^{B} P_b(c_i \mid \mathbf{x})$$The top three crops with the highest probability are returned in descending order with percentage confidence bars.---4. Fertilizer Recommendation Model (Decision Tree Prototype)4.1 Algorithm & Training SetupThe fertilizer advisory engine utilizes a `DecisionTreeClassifier` (`fertilizer_dt_prototype.pkl`, `max_depth=10`, `min_samples_split=5`) trained on the Kaggle Fertilizer Prediction dataset (99 rows).Features (8): `temperature`, `humidity`, `moisture`, `soil_type` (label-encoded), `crop_type` (label-encoded), `nitrogen`, `potassium`, `phosphorus`.Target Classes (7 fertilizers): Urea, DAP, 14-35-14, 28-28, 17-17-17, 20-20, 10-26-26.4.2 Critical Domain Safeguards & Scientific LimitationsThe evaluation panel must note that the fertilizer model is explicitly labeled as a Prototype (`prototype_kaggle_v1.0`). To ensure engineering and scientific integrity, two safeguards were implemented in the inference pipeline:Scientific Crop Mapping & Withholding:The Kaggle fertilizer dataset contains only 12 crop categories (`Paddy`, `Wheat`, `Barley`, `Maize`, `Millets`, `Cotton`, `Kidneybeans`, `Sugarcane`, `Tobacco`, `Ground Nuts`, `Pulses`, `Oil seeds`).The crop recommendation model predicts 22 crops.The backend maps 10 botanical equivalents (e.g. `rice` $\rightarrow$ `Paddy`, `chickpea`/`lentil` $\rightarrow$ `Pulses`).For the remaining 12 unsupported crops (fruits, coffee, etc.), the backend strictly withholds prediction, returning `fertilizer: "N/A"` with an advisory note explaining that fertilizer advice cannot be inferred reliably for non-field crops without empirical calibration.Alluvial Soil Texture Safeguard:The fertilizer training dataset includes only 5 soil types: `Black`, `Clayey`, `Loamy`, `Red`, `Sandy`.The MobileNetV2 CNN predicts geological soil orders, including Alluvial soil.Because Alluvial soil exhibits widely varying physical textures (from sandy loam in active river floodplains to dense clay in deltas), passing "Alluvial" into the Decision Tree causes unverified encoder assumptions.Safeguard Rule: If Alluvial soil is classified, the backend withholds fertilizer prediction and prompts the user to confirm the physical soil texture (`Black`, `Clayey`, `Loamy`, `Red`, `Sandy`). Once confirmed, the validated texture is passed into the model.---5.
